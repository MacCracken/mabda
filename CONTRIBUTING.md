# Contributing to Mabda

Thank you for your interest in contributing to Mabda.

## Prerequisites

- [Cyrius](https://github.com/MacCracken/cyrius) 5.5.11+ (ships `cc5`,
  `cyrius` CLI, and the stdlib mabda depends on)
- gcc (for GPU integration test only — links Cyrius `.o` with wgpu-native)
- Vulkan drivers (for the GPU integration test)

Everything else (lint, fmt, vet, test, bench, distlib) is driven through
the `cyrius` CLI. See `CLAUDE.md` for the full development process.

## Development Workflow

1. Fork and clone the repository
2. Resolve stdlib deps: `cyrius deps` (creates `lib/` symlinks)
3. For GPU work: `sh deps/fetch-wgpu.sh` (one-time, downloads
   wgpu-native v29 binaries into `deps/wgpu-native/`)
4. Make changes under `src/`, `tests/tcyr/`, `tests/bcyr/`, or
   `programs/`
5. Run the full gate sweep: `make test-all`
6. For GPU-path changes: `make test-phase0`
7. Submit a PR

## Project Structure

```
src/                29 domain modules — flat, zero transitive includes
src/lib.cyr         The single include chain (stdlib + domain modules)
tests/tcyr/         Consolidated CPU-only suite — `cyrius test`
tests/bcyr/         CPU-only benchmarks — `cyrius bench`
programs/           smoke.cyr (link-check), phase0.cyr (GPU integration)
deps/               C launcher + wgpu-native binaries (gitignored)
dist/mabda.cyr      Generated by `cyrius distlib`
cyrius.cyml         Package manifest (toolchain pin, [lib], [deps])
Makefile            Thin wrapper over `cyrius` CLI + GPU path
```

## Running Tests

```sh
# CPU-only unit suite (286 assertions)
cyrius test tests/tcyr/mabda.tcyr

# CPU-only benchmark harness
cyrius bench tests/bcyr/mabda.bcyr

# GPU integration (requires Vulkan + wgpu-native)
make test-phase0

# Full local gate sweep (lint, fmt, vet, version-check, dist-sync, tests)
make test-all
```

## Adding a Module

1. Create `src/mymodule.cyr` with a `# @public` or `# @internal`
   marker on line 1 and a struct-layout comment block
2. Add `include "src/mymodule.cyr"` in `src/lib.cyr` in dependency
   order
3. Add `"src/mymodule.cyr"` to the `[lib] modules = [...]` list in
   `cyrius.cyml`
4. Add tests in `tests/tcyr/mabda.tcyr` (append to the consolidated
   file; give the fn a `test_` prefix)
5. Regenerate the bundle: `cyrius distlib` (CI diff-checks this)
6. Update CHANGELOG.md

## Code Style

- Use `#` comments (not `//`)
- Prefix private functions with `_`
- Document struct layouts with byte-offset comment blocks
- Use `alloc(N)` for heap structs, `store64`/`load64` for field access
- Error handling via tagged unions (`Ok(v)` / `Err(gpu_err(...))` from
  `lib/tagged.cyr` + `src/error.cyr`)
- No panics — return GpuResult and let the caller decide
- Use `f64_*` builtins for float math, `f64_to_f32` at the GPU boundary
- Every `a * b`, `a + b`, `a / b` on sizes / dimensions gets an
  overflow or divide-by-zero guard (see the Security Hardening section
  of `CLAUDE.md`)
- `cyrius fmt` is the arbiter of formatting; CI fails on drift

## Security Audit Pass

Before a minor / major bump, run the P(-1) scaffold-hardening pass
from `CLAUDE.md`:

1. Cleanliness gates green (lint, fmt, vet, version-check)
2. Full test + bench pass
3. Per-module code walk against the Security Hardening checklist
4. External CVE sweep (wgpu-native / GPU drivers)
5. File findings in `docs/audit/YYYY-MM-DD-audit.md` (see
   `2026-04-19-audit.md` for the yukti-style template)
6. Fix HIGH and MED findings with regression assertions
7. Schedule LOW findings

## Commit Messages

Follow [Keep a Changelog](https://keepachangelog.com/) categories:
- `add: feature description` for new features
- `fix: bug description` for bug fixes
- `change: what changed` for modifications
- `audit: finding N fix` for findings from a security audit
