# v3.4 Proposal — Array Textures + Cubemaps (Phase AA / AL-ARRAY)

**Status:** accepted, in progress (`34x`, toolchain 6.2.26).
**Planned:** 2026-06-19, from the `v34-al-array-plan` design workflow (4 research
dimensions — native GFX9 / wgpu / container loaders / mabda API — + synthesis).
**Bite breakdown + gates:** [`3-4-punchlist.md`](../development/3-4-punchlist.md).

## Problem

mabda samples single-layer 2D textures and loads single-image DDS/KTX2/PNG. The
v3.3 loaders already **parse** `arraySize` / `faceCount` / `layerCount` from DDS
and KTX2 — and fail loud (`GPU_ERR_FORMAT_UNSUPPORTED`). Consumers (soorat skybox,
texture atlases, material arrays) need **2D array textures** and **cubemaps**.
v3.4 turns the parse-and-reject paths into create + upload + sample + load.

## Constraints

- **Additive only.** No existing public call signature changes (the v3.0
  load-bearing invariant — consumers' single-2D code keeps compiling and behaving
  identically). New entry points, not widened ones.
- **Dual backend.** wgpu + native AMD GFX9, same public surface, slot-routed.
- **Native HW-verified on Cezanne** (gfx90c); wgpu CPU-asserted locally (the dev
  box is the native GPU — see the wgpu-box gate).
- **Untrusted-input discipline.** The loaders' new per-layer offset math inherits
  the 3.3.0 KTX2 overflow-safety audit.

## Key design decisions

### 1. New Backend slots, not widened ones (forced, not preferred)

mabda routes public calls through fixed-arity `fncallN(slot, …)`. The existing
`create_2d_fmt_mipped` and `write_level` are already `fncall5` — a `layers` /
`layer` argument **physically cannot** fold in. So AA.0 adds three new slots
(`TEXTURE_CREATE_2D_ARRAY`, `TEXTURE_CREATE_CUBE`, `TEXTURE_WRITE_LAYER_LEVEL`),
`BACKEND_SIZE 296 → 320`, reserved up front so native (AA.1) and wgpu (AA.3)
fillers slot in without renumbering. This mirrors how AL.1/AL.2 appended slots at
280/288 in v3.3.

### 2. Cube = a 6-slice 2D array on GFX9

On GFX9 a cubemap is a 2D array with `TYPE=CUBE(11)` and `DEPTH = 6·ncube − 1`;
storage is 6 contiguous face slices. So the cube create/upload path is the
2D-array path with `slice_count=6` + a different T# `TYPE` — most of AA.5 reuses
AA.1. The face order is the D3D/KTX2 canonical **+X, −X, +Y, −Y, +Z, −Z**.

### 3. One BO per array; slice k at `base + k·slice_pitch`

An N-slice array is a single (larger) BO, so residency / bind / USER_DATA wiring
is unchanged from single-2D. `slice_count` is stashed in the `NativeTexture +60`
pad (struct stays 64 B). LINEAR `slice_pitch` = per-slice surface size; the
**tiled** slice stride is an addrlib question (AA.4a gate) resolved before any
tiled-compressed-array HW.

### 4. Per-draw layer selection via the descriptor tail

The native sampling FS learns the layer through the existing per-draw descriptor
tail (`scale_x@+48 / scale_y@+52` → add `layer@+56`), s-loaded and moved into the
3rd MIMG VADDR. This fixes **one sampled layer per draw** — sufficient for the
loader → sample path. Selecting a layer per-fragment, or **rendering INTO** array
layers / cube faces (layered render), is **out of scope** for this arc and stays
flagged for a later one.

### 5. Native sampling ISA deltas

Both existing FS hardcode `MIMG DA=0` + 2 VADDR. A 2D-array sample sets `DA=1`
(`w0 |= 1<<14`) and adds a 3rd VADDR = integer slice index. A **cube** sample is
a genuinely new FS: `DA=1` with a float direction (s/t/r) the TA resolves to
face + per-face u/v — no existing FS reuses this, which makes **cube sampling the
single biggest Cezanne HW risk**. Mitigation: AA.5 ships cube **storage**
(AA.5a, low risk) independently of cube **sampling** (AA.5b); if Cezanne TA cube
filtering proves unreliable, the sampling FS is gated and `caps_cube` stays 0 —
cube storage still ships, nothing silently dropped.

### 6. Container data ordering (HW-verified, not assumed)

KTX2 is **mip-outer, layer-inner**: one level's `byteLength` covers all
layers·faces, per-image stride = `blen / (layers·faces)`. DDS is **surface-major,
mip-inner**. The loaders flip their rejects to an outer layer/face loop. The
spec-stated ordering and the +X..−Z ↔ backend-layer-index mapping must agree with
the GFX9 CUBE T# and the wgpu Cube view — settled by a per-face distinct-color HW
test (AA.7a), not on CPU alone.

### 7. Overflow-safe per-layer offset math (carry the 3.3.0 audit)

`per_image = blen / total_images` (with `total_images != 0` guard +
`blen % total_images != 0` reject) and `sub_off = boff + image_idx·per_image`
with the `sub_off > len − per_image` no-overflow check **re-applied per layer** —
because now both the divisor (`total_images`) and the multiplier (`image_idx`)
come from untrusted header fields. Regression asserts that would catch a
malicious header land with AA.6.

## Alternatives considered

- **Widen `create_2d_fmt_mipped` to carry `layers`.** Rejected — breaks the
  fixed `fncall5` arity and the additive invariant; a new slot is mandatory.
- **A separate BO per array slice.** Rejected — multiplies residency/bind
  bookkeeping and BO count; GFX9 expects one array surface.
- **Cube via 6 separate 2D textures + manual face select.** Rejected — loses HW
  cube filtering (seamless edges) and the single-`textureSample(cube, dir)` API.
- **Per-fragment layer / layered render now.** Deferred — the descriptor-tail
  one-layer-per-draw covers the loader/sample use case; layered render is a
  larger, separate capability.

## Out of scope / gated (tracked, not dropped)

- Layered **render** (rendering INTO array layers / cube faces) — later arc.
- **Cube-array** (KTX2 layerCount≥1 ∧ faceCount==6; DDS arraySize·6) — the parser
  keeps `total_images = layers·faces` general, but cube-array **create** stays
  rejected until a HW test exists.
- **ETC2/ASTC** array/cube on native — HW-blocked on AMD (BC-only, unchanged).
- **wgpu HW verification** — box-dependent; ships CPU-asserted with the HW e2e
  gated where a wgpu box is unavailable.
