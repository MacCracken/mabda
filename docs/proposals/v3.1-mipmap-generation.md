# Proposal: v3.1 On-Device Mipmap Generation (both backends)

**Status:** Proposed (v3.1.0 design).
**Date:** 2026-06-15.
**Arc:** First feature of the v3.1.x arc — see
[`docs/development/3-1-punchlist.md`](../development/3-1-punchlist.md).
**Roadmap:** [`roadmap.md` § v3.1](../development/roadmap.md#v31--mipmaps--multi-queue-consumer-catch-up).
**Companion:** [`v3.1-multiqueue.md`](v3.1-multiqueue.md) (the arc's second
feature, 3.1.1+).

## Summary

Add on-device mipmap-chain generation: a consumer creates a texture with
N mip levels, uploads level 0, and asks mabda to fill levels 1..N-1 by
GPU downsampling. The public API is identical on both backends; the
backend slot impls differ (wgpu: texture views + a WGSL box-filter
compute shader; native AMD: a hand-authored GFX9 ISA downsample shader +
PM4 + descriptor table). This is the **self-contained, lower-risk** half
of v3.1 and ships first as 3.1.0.

**It does not depend on multi-queue.** Per-level ordering is a
read-after-write hazard between consecutive compute dispatches; on a
single queue that is handled by a cache flush/invalidate between
dispatches — and mabda already shipped that PM4 primitive
(`native_pm4_event_write_cache_flush_and_inv`, Step 6.10) for exactly
this class of barrier. So mipmaps land before multi-queue, not after.

## Current state (what exists today)

- **No mip support anywhere.** `wgpu_texture_descriptor` always implies a
  single level; `WGPUTextureViewDescriptor` hardcodes
  `baseMipLevel`/`mipLevelCount` = 0/1 (`src/wgpu_descriptors.cyr:437-438`).
  The v2 `texture_create_rgba8` and the v3 `gpu_texture_create_2d_rgba8`
  (`src/texture.cyr`) take only `(w, h)` — no `mip_count`.
- **Native texture is single-level.** `NativeTexture` is a 32-byte struct
  (`handle/va/addr/size`); `native_texture_create_2d_rgba8` allocates one
  GTT BO of `w*h*4` and va-maps it at a single hardcoded VA
  (`_NATIVE_TEXTURE_VA_BASE = 0xFFFF800100A00000`) with ~4 MiB headroom
  (`src/backend_native.cyr`).
- **Storage-texture binding is scaffolded but unwired** on wgpu
  (`WGPU_TEXTURE_USAGE_STORAGE_BINDING` exists; the storageTexture
  bind-group-layout-entry path at `src/wgpu_descriptors.cyr:~266` is not
  built). Compute bind groups today are storage-*buffer* only
  (`src/compute.cyr`).
- **The barrier primitive exists.** `native_pm4_event_write_cache_flush_and_inv`
  + the `CACHE_FLUSH_AND_INV` event constant landed in Step 6.10 (see
  `docs/development/3-0-punchlist.md` "6.10 prep"). It was built for the
  render path's end-of-frame flush; it is exactly the inter-level barrier
  mipmap generation needs.

## Public API (identical on both backends — ADR 005)

Two additions, both `# @public`:

```cyrius
# Create a 2D RGBA8 texture with a mip chain. mip_count == 1 is the
# existing single-level behavior; mip_count == 0 means "full chain"
# (floor(log2(max(w,h))) + 1). Levels are allocated but only level 0 is
# defined until gpu_texture_generate_mipmaps runs.
fn gpu_texture_create_2d_rgba8_mipped(ctx, width, height, mip_count): i64

# Fill levels 1..N-1 from level 0 by GPU 2x2 box-filter downsample.
# Returns 0 | GPU_ERR_*. Levels must have been allocated by the create
# call above; level 0 must already be written.
fn gpu_texture_generate_mipmaps(ctx, tex): i64
```

`gpu_texture_create_2d_rgba8(ctx, w, h)` stays as the single-level entry
(it forwards `mip_count = 1`). The existing input-validation guards from
the 3.0.4 audit (positivity, `MABDA_MAX_TEXTURE_DIM_2D`, overflow) apply,
plus a `mip_count` bound: `1 <= mip_count <= floor(log2(max(w,h)))+1`.

## Backend interface changes

Append after the surface slots (offsets 0..200 are load-bearing; the
append-after-KIND policy holds). Two new slots:

| Slot | Offset | Signature |
|------|--------|-----------|
| `BACKEND_SLOT_TEXTURE_CREATE_2D_RGBA8_MIPPED` | 208 | `(ctx, w, h, mip_count) -> tex_ptr` |
| `BACKEND_SLOT_TEXTURE_GENERATE_MIPMAPS` | 216 | `(ctx, tex) -> 0\|err` |

`BACKEND_SIZE` grows 208 → 224. Add a `BACKEND_MIPMAP_SLOTS_BEGIN/END`
range marker pair (208/224) and extend `backend_is_complete`'s walk to
cover it. Both backends must fill both slots before the slots exist in
tree (no `GPU_ERR_NOT_IMPLEMENTED` stub slots — ADR 006 fail-loud).
`backend_wgpu_new` / `backend_native_new` install them.

(Rationale for two slots, not one: `create_mipped` is a 4-arg allocation
returning an opaque tex_ptr; `generate` is a 2-arg dispatch. They have
different arities and lifetimes; keeping them separate matches the
texture-slot group's shape and stays within the fncall ceiling.)

## wgpu backend impl

Straightforward — WebGPU has first-class mip support:

1. **`create_mipped`** — `wgpu_texture_descriptor` with
   `mipLevelCount = mip_count` and usage
   `TEXTURE_BINDING | COPY_DST | STORAGE_BINDING` (storage needed so the
   downsample shader can write level n+1). Build and stash N
   `WGPUTextureView`s (one per level, `baseMipLevel = i`,
   `mipLevelCount = 1`). The wgpu texture struct is 32 bytes and opaque;
   rather than grow it (backward-incompatible), keep the per-level view
   array in a **context-local table keyed by the texture handle** (the
   map find from `pipeline_cache`/`bind_group_cache` is the precedent).
2. **`generate`** — a small mabda-provided WGSL 2×2 box-filter compute
   shader (`@group(0) @binding(0)` = sampled view of level n,
   `@binding(1)` = storage view of level n+1). For each level i in
   1..N-1: bind (view[i-1], view[i]), dispatch
   `ceil(w_i/8) × ceil(h_i/8)`, relying on the single queue's submit
   ordering for the read-after-write hazard (a barrier per level is
   implicit in separate submits, or one encoder with the wgpu
   memory-model's automatic usage transitions).
3. Wire the storage-texture bind-group-layout entry path that is
   currently scaffolded (`src/wgpu_descriptors.cyr:~266`).

The WGSL downsample shader ships in mabda (it is mabda-internal
generation, not consumer shader code), so this does not depend on the
consumer's shader bundle.

## native AMD backend impl — the crux

WGSL→GFX9 lowering is **not** in scope here (deferred to v3.x, 10–16
weeks per `v3-wgsl-frontend-choice.md`). The downsample shader is
**hand-authored GFX9 ISA**, exactly the method used for the existing
`native_gfx9_shader_store_deadbeef` / fullscreen-triangle shaders
(clang `-target amdgcn--amdhsa -mcpu=gfx90c` of an equivalent kernel,
ground-truthed with `llvm-objdump`, byte-pinned with CPU asserts; see
`feedback_verify_gfx9_shader_bytes_with_llvm_mc`).

Three pieces of new native infrastructure:

1. **Mipchain BO + VA layout.** Allocate one GTT BO holding all levels
   contiguously: `offset_M = Σ_{k<M} align(w_k * h_k * 4)`, total
   ≈ 1.333 × base (geometric series). Grow `NativeTexture` to carry
   `mip_count` + the per-level byte offsets (or a parallel mip-metadata
   table in the GpuContext-side cache, mirroring the wgpu view table).
   Generalize the single hardcoded `_NATIVE_TEXTURE_VA_BASE` into a small
   VA sub-allocator (the 4 MiB headroom is insufficient for chains).
2. **Descriptor table (image V# descriptors).** image_load/image_store
   need a 256-byte-aligned descriptor table of 16-byte V# entries
   (base VA, width/height/pitch, format = RGBA8_UNORM). New
   `native_descriptor_table_*` builders (~200 lines, BO allocator +
   `SET_SH_REG` of `COMPUTE_USER_DATA_*` to the table VA). This is the
   genuinely new PM4 code path; it follows existing patterns but the V#
   field encoding is GFX9-specific and ABI-risky — cross-check against
   the AMD ISA reference + radv.
3. **Downsample shader + PM4 composer.**
   `native_gfx9_shader_downsample_2x2` (~100–200 bytes: image_load 4
   texels, average, image_store 1) and
   `native_pm4_build_compute_downsample(buf, src_mip_va, dst_mip_va, w, h)`.
   The `generate` slot loops levels 1..N-1: build PM4 for the level,
   dispatch via the existing `native_compute_dispatch_cached` path,
   **emit `native_pm4_event_write_cache_flush_and_inv` between levels**
   so level n's writes are visible to level n+1's reads (the
   single-queue barrier — no multi-queue needed).

**Risk:** image_load/store ISA + V# descriptors are the hardest new
native work since the render bring-up; budget 2–4 HW iteration cycles on
Cezanne (TDR debugging is familiar from Phase B.4/C). If the descriptor-
table infra slips, mipmap generation can move to 3.2 without disturbing
multi-queue (3.1.1) — the two are independent.

## Phasing (sub-bites, mirroring the 3.0 punchlist granularity)

See the punchlist for the checkbox list; the shape is:
- Mip storage + VA sub-allocator + `create_mipped` (both backends)
- Per-level access (wgpu views table / native descriptor table)
- Downsample shader (wgpu WGSL + native hand-authored ISA, byte-pinned)
- PM4 compute-downsample composer + inter-level barrier (native)
- `generate` dispatchers + the public API + slot wiring
- `programs/native_mipmap_e2e.cyr` + `programs/mipmap_e2e.cyr` (wgpu) —
  generate a chain from a known level-0 pattern, CPU-read each level,
  verify 2×2 averaging numerically

## Exit criteria (3.1.0)

- Public `gpu_texture_create_2d_rgba8_mipped` + `gpu_texture_generate_mipmaps`
  on both backends; both slots filled (`backend_is_complete` = 1).
- CPU suite: mip-count validation, slot wiring, BO/VA offset math,
  descriptor-table layout, downsample shader bytes pinned — every new
  path adds an assertion (house rule).
- On AMD: `native_mipmap_e2e` generates a correct chain from a level-0
  checkerboard; each level verified as the 2×2 average of its parent
  (CPU readback, numeric).
- wgpu: `mipmap_e2e` passes; cross-backend the generated chains match
  within rounding (the v3.0 cross-backend-identity posture).
- lint / fmt / vet / distlib / version-check clean; `dist/mabda.cyr`
  regenerated; CHANGELOG `[3.1.0]` section; audit re-run if any
  FFI/buffer/texture math changed (P(-1) work loop step 5).
