# Proposal: v3.2 Native Compressed-Texture Sampling on GFX9 (T#/tiling/sampler/image_sample)

**Status:** Proposed (v3.2.x design — Phase TS, lands after Phase T).
**Date:** 2026-06-15.
**Arc:** Within the v3.2.x "texture & shader breadth" arc — see
[`roadmap.md` § v3.2](../development/roadmap.md#v32--texture--shader-breadth)
and [`docs/development/3-2-punchlist.md`](../development/3-2-punchlist.md).
**Depends on:** Phase T (`v3.2-compressed-textures.md`) — the format table,
block math, `BACKEND_SLOT_TEXTURE_CREATE_2D_FMT` (+248), and the
`GPU_ERR_FORMAT_UNSUPPORTED` (=19) code. This proposal **removes the
storage-only native limitation** Phase T documented.
**Companion:** [`v3.2-compressed-textures.md`](v3.2-compressed-textures.md)
(the limitation), [`v3.1-mipmap-generation.md`](v3.1-mipmap-generation.md)
(the PIVOT that deleted T#/V#).

## Summary

Re-introduce the GFX9 image-descriptor (T#) + sampler (S#) + tiled-surface
+ `image_sample`/`image_load` infrastructure that the v3.1 mipmap PIVOT
deleted, so the **native AMD** backend can **sample** textures in a
fragment shader — not just store and read them back. The first consumer
of this path is compressed-texture sampling (BC/ETC2/ASTC), which Phase T
shipped as `GPU_ERR_NOT_IMPLEMENTED` on native; the same machinery is the
foundation for general native texture sampling (the solid-red FS becomes a
textured FS).

The work is five concrete pieces:

1. **A 256-bit GFX9 T# image descriptor builder** — pure-Cyrius byte
   writer that encodes base VA, width/height, format, swizzle, and
   **tiling mode** into the 8-dword resource word, citing Mesa
   `gfx9.json` / radv `ac_surface` field offsets.
2. **A 128-bit GFX9 S# sampler descriptor builder** — filter modes,
   address modes (clamp/wrap), LOD clamps; the simplest viable
   point/bilinear sampler first.
3. **A tiled (sampler-compatible) surface layout** for sampleable
   textures — the hard-truth fork below: BC hardware decode needs a
   non-linear micro-tile mode, so a sampleable texture is **not** the
   linear storage BO Phase T creates.
4. **A textured fragment shader in hand-authored GFX9 ISA** —
   `native_gfx9_shader_textured_fs` using `image_sample` (MIMG) reading
   the T#/S# from SGPRs, replacing `native_gfx9_shader_solid_red` on the
   sample path; later regenerated by the Phase N compiler.
5. **Two Backend slots** — `create-sampleable` (allocates the tiled BO +
   builds + stashes the T#) and `bind-for-sample` (binds T#/S# into the
   render pass's PM4 so the FS reads it), plus the FS-input/SPI wiring the
   solid-red path never needed.

The public API stays the same shape on both backends (ADR 005); the
backends differ in tiling capability (ADR 006). This is the piece the
maintainer pulled out of "v4-scale" into the 3.2.x arc.

## Hard truth up front: sampleable ≠ the linear storage BO, and BC decode needs tiling

This is the constraint that shapes the whole design — stated before the
API so it is not relitigated mid-arc.

Native textures today are **linear GTT BOs**: `COLOR_SW_MODE = 0`
(`GFX9_CB_COLOR0_ATTRIB_2D_LINEAR_RGBA8 = 0x10000000`,
`backend_native_shaders.cyr:953`), no DCC (`DCC_ENABLE = 0`,
`backend_native_pm4.cyr:988`), no swizzle. The whole native texture story
is "the BO's bytes *are* the pixels; write/read collapse to memcpy"
(`_backend_native_texture_write`/`_read`, `backend_native.cyr:751/764`).
The v3.1 mipmap PIVOT deleted the T#/V# descriptor design *because* linear
layout let the downsample shader use flat `global_load`/`global_store`
(`v3.1-mipmap-generation.md` § PIVOT; `native_texture_level_va`,
`backend_native.cyr:1387`).

Two facts decide the tiling question, and the proposal documents the truth
rather than hand-waving it:

- **The TA (texture-addressing) unit can sample a `SW_MODE = LINEAR`
  surface for *uncompressed* formats.** Plain RGBA8 sampling can therefore
  reuse the existing linear BO unchanged — the T#/S#/`image_sample` path
  is the only new infra for the uncompressed case. This is why "general
  native texture sampling" is a strictly smaller problem than "compressed
  sampling" and is sequenced first (TS.5 below).
- **Block-compressed (BC/ETC2/ASTC) hardware decode requires a non-linear
  micro-tile layout.** The TA's block-decode addressing on GFX9 assumes a
  tiled `SW_MODE` (the `_S`/`_D` standard/displayable swizzle family); a
  `LINEAR` compressed surface is not a supported decode input on Cezanne.
  So a *sampleable compressed* texture must be allocated in a tiled
  `SW_MODE`, and the opaque blocks the consumer uploads must be **swizzled
  into the tile layout** at write time (a tiling transform, not a memcpy).

The honest consequence: **uncompressed sampling (linear BO + T#/S#) and
compressed sampling (tiled BO + swizzle + T#/S#) are two sub-features.**
Both are in this proposal and both land in the 3.2.x arc; the tiling
swizzle is the high-risk, HW-iteration-heavy half, and is sequenced last
with its own bites. Neither is deferred past 3.2.x.

## Current state (what exists today)

- **No T#/S#/image instructions anywhere.** The only "V#" references left
  in `src/` are (a) the Mesa scratch-V# *stub* a compute shader's
  USER_DATA_2/3 points at (`backend_native_shaders.cyr:95`,
  `backend_native_pm4.cyr:532`) — a placeholder, not a real sampled
  resource — and (b) comments noting the 256-byte per-level mip alignment
  was kept "so it can seed a GFX9 image descriptor (V#)"
  (`backend_native.cyr:1344`). The PIVOT deleted the builder; the
  alignment foresight remains.
- **The render FS samples nothing.** `native_gfx9_shader_solid_red`
  (`backend_native_shaders.cyr:301`) writes four hardcoded f32 channels
  and `exp mrt0` — no memory op, `SPI_PS_INPUT_ENA` set only to the
  hang-quirk minimum `0x2` (PERSP_CENTER), `SPI_PS_IN_CONTROL = 0`, no
  varyings (`GFX9_SPI_VS_OUT_CONFIG_NO_VARYING`,
  `backend_native_pm4.cyr:771-775`). There is no UV interpolation, no S#,
  no T#.
- **Native textures are single-VA linear BOs.** `native_texture_create_2d_rgba8`
  (`backend_native.cyr:1399`) allocates `w*h*4` via `native_bo_create_gtt`
  + `native_gem_va_map(..., _NATIVE_PERM_DATA)`; `NativeTexture` is 48
  bytes (`backend_native.cyr:1325-1332`: handle/va/addr/size/width/height/
  mip_count + 4-byte pad). No format field, no tiling field, no T# stash.
- **The render pipeline carries only VS+FS VAs.** `NativeTexture`'s
  consumer is the FS via `native_render_pipeline_pack` →
  `NATIVE_PIPE_FIELD_*` (`backend_native.cyr:1628`): VS/FS handle+VA + a
  pre-built SH block (56 B) + CTX block (556 B). There is no slot for a
  bound texture's T#/S# in the pipeline or the pass struct
  (`NATIVE_PASS_FIELD_CTX/RT/CLEAR_COLOR`).
- **Phase T (3.2.0) ships the format table + storage path.** After Phase
  T, `BACKEND_SIZE = 256`, `BACKEND_SLOT_TEXTURE_CREATE_2D_FMT` at +248,
  `GPU_ERR_FORMAT_UNSUPPORTED = 19`, `gpu_texture_create_2d(ctx,w,h,fmt)`,
  `mabda_texfmt_*` accessors, and a compression cap bitset at
  `GpuCapabilities+120`. **This proposal flips the native compressed
  bits from 0 to "sampleable" once TS lands.**
- **256-byte alignment + the texture VA region are ready.** The 2 GiB
  texture VA region (`_NATIVE_TEXTURE_VA_BASE = 0xFFFF800180000000`,
  64 KiB-aligned allocs, `backend_native.cyr:1304`) and the 256-byte
  per-level alignment already accommodate a tiled multi-level surface; the
  GEM_VA map already needs (and uses) 4 KiB-aligned sizes
  (`reference_gem_va_map_page_align`).

## The GFX9 T# image descriptor (256-bit, 8 dwords)

The resource descriptor a `image_sample`/`image_load` reads from an SGPR
pair (the SGPRs hold the *address* of the 8-dword descriptor, or the
descriptor is loaded into 8 consecutive SGPRs via `s_load_dwordx8`). Field
layout is the GFX9 `V# / T#` image-resource format; every offset is cited
against Mesa `gfx9.json` (the authoritative register source per
`feedback_gfx9_register_authoritative_source`) and radv `ac_surface` /
`si_make_texture_descriptor`. A builder writes it into a caller buffer:

```cyrius
# Build a 256-bit (8-dword) GFX9 T# image descriptor into buf at pos.
# base_va: 256-byte-aligned GPU VA of the surface (tiled or linear).
# fmt: a MABDA_TEXFMT_* id (Phase T table) -> mapped to a GFX9 IMG
#      data-format + num-format pair.
# sw_mode: GFX9 SW_MODE swizzle (LINEAR for uncompressed; a tiled
#          _S/_D mode for compressed — see surface layout below).
# Returns pos + 32.   # @internal
fn native_gfx9_image_descriptor(buf, pos, base_va, width, height,
                                fmt, sw_mode, mip_count): i64
```

Dword map (GFX9 image V#; field names from radv/Mesa, each to be pinned
with a CPU assert and cross-checked against `gfx9.json` before the first
HW run):

| DW | Field(s) | Source |
|----|----------|--------|
| 0 | `BASE_ADDRESS[39:8]` = `base_va >> 8` (logical `>>`, mask) | radv `tex.surface.tile_swizzle`/base |
| 1 | `BASE_ADDRESS_HI[7:0]` + `MIN_LOD` + `DATA_FORMAT[5:0]` (start) | GFX9 V# word1 |
| 2 | `WIDTH[13:0]` (= w-1) + `NUM_FORMAT` + `DST_SEL_{X,Y,Z,W}` | GFX9 V# word2 |
| 3 | `HEIGHT[13:0]` (= h-1) + `TYPE[3:0]` (= SQ_RSRC_IMG_2D) + `BASE_LEVEL` | GFX9 V# word3 |
| 4 | `DEPTH`/`PITCH`/`LAST_LEVEL` + `SW_MODE[4:0]` (swizzle) | GFX9 V# word4 — **the tiling field** |
| 5 | `META_DATA_ADDRESS`/`META_PIPE_ALIGNED` = 0 (no DCC) | GFX9 V# word5 |
| 6–7 | DCC/metadata extents = 0 (uncompressed-meta) | GFX9 V# word6/7 |

The `DATA_FORMAT`/`NUM_FORMAT` pair is where compressed formats live: BC1
= `IMG_DATA_FORMAT_BC1`, BC3 = `_BC3`, …, ETC2/ASTC = their GFX9 image
data-format enums. A `fn native_gfx9_texfmt_to_img_format(fmt)` returns
the `(data_format, num_format)` pair, the T# analog of Phase T's
`mabda_texfmt_to_wgpu` — table-driven, one row per format, every row
CPU-pinned. (Cezanne/gfx90c is RDNA2-era APU silicon with the GFX9 image
pipeline; ASTC HW decode presence is a HW-verification item, flagged
below.)

## The GFX9 S# sampler descriptor (128-bit, 4 dwords)

```cyrius
# Build a 128-bit (4-dword) GFX9 S# sampler descriptor into buf at pos.
# filter: NATIVE_SAMP_FILTER_POINT | _BILINEAR
# addr:   NATIVE_SAMP_ADDR_CLAMP | _WRAP   (applied to U+V)
# Returns pos + 16.   # @internal
fn native_gfx9_sampler_descriptor(buf, pos, filter, addr): i64
```

Dword map (GFX9 S#; XY_MAG/MIN_FILTER, CLAMP_X/Y/Z, MIN/MAX_LOD,
FILTER_MODE). The first sampler is **point filtering, clamp-to-edge** —
the minimal viable sampler, deterministic and CPU-verifiable. Bilinear
(`XY_*_FILTER = BILINEAR`) follows as a one-field change with its own
numeric test. The S# lives next to the T# in the same descriptor BO
(16 bytes after the 32-byte T#).

## Sampleable surface layout (the linear/tiled fork)

A sampleable texture is **not** the Phase T storage BO. It is a new BO
shape, allocated through the same `native_bo_create_gtt` +
`native_gem_va_map` machinery (`_NATIVE_PERM_DATA`, 4 KiB-aligned size,
the 2 GiB texture VA region) but with a tiling decision per format:

- **Uncompressed (RGBA8) sampleable** → `SW_MODE = LINEAR`. The BO bytes
  are still the pixels; write/read stay memcpy. Only the T#/S#/FS path is
  new. This is TS.5 — the lowest-risk slice and the one that proves the
  T#/S#/`image_sample` plumbing independently of tiling.
- **Compressed sampleable (BC/ETC2/ASTC)** → a tiled `SW_MODE`
  (`SW_64KB_S` standard swizzle, the radv default for GFX9 sampled
  images). The consumer's opaque blocks must be **swizzled into the tile
  layout on write** — a pure-Cyrius address-remap (`native_tile_swizzle_bc`)
  computing, per source block, its tiled byte offset from the GFX9
  micro-tile equations (radv `ac_surface` / `addrlib` `gfx9_swizzle`).
  `read` reverses it (de-swizzle) so round-trip stays byte-identical to
  the bytes the consumer wrote. This is the HW-iteration-heavy half.

Surface size for a tiled compressed BO is `_native_align_up` of the
swizzled extent (tiling rounds width/height up to tile multiples), sized
in blocks via Phase T's `mabda_texfmt_data_size` then padded to the tile
footprint — re-derived with an explicit overflow guard (the worst case is
still well inside i64; 64 KiB tile padding on 8192²/4×4 blocks stays
< 128 MiB).

A new `NativeTexture` field carries the tiling mode + format so write/read
know whether to memcpy or swizzle, and the T# builder knows the `SW_MODE`.
`NativeTexture` grows 48 → 64 bytes (append-only; offsets 0..44 unchanged):

```
+44: pad     -> repurposed: fmt        (u32, MABDA_TEXFMT_* id)
+48: sw_mode (u32, GFX9 SW_MODE)
+52: t_va    (u64, GPU VA of the 48-byte T#+S# descriptor BO)
+60: pad     (u32)
```

(`fmt` reuses the existing +44 pad; the struct grows by 16 to 64 for the
sw_mode + descriptor-VA fields. `NATIVE_TEX_STRUCT_SIZE` 48 → 64, every
allocation site already uses the constant.)

## The textured fragment shader (hand-authored GFX9 ISA)

`native_gfx9_shader_solid_red` becomes `native_gfx9_shader_textured_fs`:
a fragment shader that interpolates a UV varying and issues an
`image_sample` (MIMG) reading the T# (8 SGPRs) + S# (4 SGPRs), then
`exp mrt0` of the sampled RGBA. Authored exactly the way every existing
native shader was — `llvm-mc -triple=amdgcn--amdhsa -mcpu=gfx90c`,
round-trip-verified via `scripts/disasm-shaders.sh`, byte-pinned with CPU
asserts (`feedback_verify_gfx9_shader_bytes_with_llvm_mc`).

This shader needs FS-input wiring the solid-red path never set up:

- `SPI_PS_INPUT_ENA` must enable a real interpolant (PERSP_CENTER for the
  UV varying) — the current `0x2` hang-quirk minimum *happens* to be
  PERSP_CENTER, so the bit is already there, but the UV varying must
  actually be exported by the VS and consumed (`SPI_VS_OUT_CONFIG` /
  `SPI_PS_IN_CONTROL` gain a param). The VS
  (`native_gfx9_shader_fullscreen_triangle_vs`) gains a UV export
  (`exp param0`) derived from vertex_id — a self-contained companion
  shader, byte-pinned.
- The T#/S# arrive in the FS's user-SGPRs (the PS USER_SGPR allocation in
  `GFX9_PS_PGM_RSRC2_MIN = 0x4` widens to load the descriptor pointer);
  `SET_SH_REG` of `SPI_SHADER_USER_DATA_PS_*` with the descriptor BO's VA
  is emitted in the pipeline SH block.
- RSRC1's VGPR/SGPR counts grow for the MIMG path (the sampled-result
  VGPRs + the 12 descriptor SGPRs); the hand-authored shader's high-water
  marks set RSRC1, exactly as the downsample shader documents its
  v0..v14 / s0..s19 usage (`backend_native_shaders.cyr:133`).

A companion `image_load` variant (`native_gfx9_shader_textured_load_fs`,
no sampler, integer coords) is authored alongside for the compressed-block
case where point sampling at exact texel centers is wanted — `image_load`
skips the S# and is the simpler bring-up oracle.

## How it threads the Backend slots

Phase T parameterized create with a format
(`BACKEND_SLOT_TEXTURE_CREATE_2D_FMT` at +248, `BACKEND_SIZE = 256`). A
*sampleable* texture has a different lifetime (it allocates a descriptor
BO and, for compressed, a tiled surface), and **binding** a texture into a
render pass is a genuinely new op with no existing slot. Two new slots,
appended after Phase T's (append-after-KIND policy holds; both backends
fill both before the completeness walk activates over the range):

| Slot | Offset | Signature |
|------|--------|-----------|
| `BACKEND_SLOT_TEXTURE_CREATE_2D_SAMPLEABLE` | 256 | `(ctx, w, h, fmt) -> tex_ptr` |
| `BACKEND_SLOT_TEXTURE_BIND_FOR_SAMPLE` | 264 | `(ctx, pass, tex, sampler) -> 0\|err` |

`BACKEND_SIZE` 256 → 272. Add a `BACKEND_SAMPLE_SLOTS_BEGIN/END`
(256/272) range-marker pair and extend `backend_is_complete`'s walk over
it (the established M.2/Q.1 discipline: layout in tree, completeness walk
when both backends fill — both do here: wgpu binds a compressed view +
sampler for real, native builds the T#/S# + tiled BO for real).

- **`create_sampleable`** differs from Phase T's `create_2d_fmt` (storage
  only): it picks the tiling mode, allocates the tiled-or-linear BO,
  builds the T# + S# into a descriptor BO, and stashes the descriptor VA
  + sw_mode in the (grown) `NativeTexture`. `write`/`read` route through
  the format/sw_mode field: memcpy for linear, swizzle for tiled.
- **`bind_for_sample`** stashes the bound tex's T#/S# VA on the pass
  struct (a new `NATIVE_PASS_FIELD_TEX_DESC_VA`); the next
  `render_pass_draw` emits the `SET_SH_REG` of `SPI_SHADER_USER_DATA_PS_*`
  with that VA and uses the textured FS pipeline. The ctx-stash precedent
  (surface card-fd at `GpuContext+96`) and the queue-table precedent
  (v3.1.1) cover the storage placement; the pass struct grows by 8 bytes
  (append-only).

The 4-arg `bind_for_sample` is within the fncall ceiling. `render_pass_draw`
stays at its 5-arg `(ctx, pass, pipe, vc, ic)` ABI — the texture is read
off the pass, not added as a param (avoiding the 6-param wgpu-fncall
ceiling and matching how RT is read off the pass today).

### wgpu side (parity, ADR 005)

wgpu already samples compressed textures (Phase T shipped create + upload
+ sample on wgpu). `create_sampleable` on wgpu builds the texture view +
its BGL entry (the M.3(wgpu) view/BGL machinery the mipmap proposal
references); `bind_for_sample` builds the bind group (texture view +
`WGPUSampler` from a sampler descriptor) and stashes it on the pass. No
new wgpu FFI beyond the sampler-create + storage/sampled view paths
already scaffolded. So the slots are real on both backends from the first
TS minor.

## Public API (identical on both backends — ADR 005)

```cyrius
# Create a 2D texture that can be SAMPLED in a fragment shader (not just
# stored). fmt is a MABDA_TEXFMT_* id. On native: allocates a tiled
# surface for compressed formats (linear for RGBA8) plus a T#/S#
# descriptor; on wgpu: a TEXTURE_BINDING view. Returns an opaque tex_ptr,
# or 0 on invalid dims / unsupported format. # @public
fn gpu_texture_create_2d_sampleable(ctx, width, height, fmt): i64

# Create a sampler (filter + address modes). # @public
fn gpu_sampler_create(ctx, filter, addr): i64

# Bind a sampleable texture + sampler into a render pass so the bound
# pipeline's FS samples it. # @public
fn gpu_render_pass_bind_texture(ctx, pass, tex, sampler): i64

# write / read accept the same (ctx, tex, src, n); native swizzles into /
# out of the tile layout for compressed sampleable textures so a
# round-trip stays byte-identical. # @public (existing dispatchers, widened)
```

`gpu_texture_create_2d` (Phase T, storage) and
`gpu_texture_create_2d_sampleable` (this proposal) are distinct entry
points: the former is the cheap linear storage BO, the latter the
descriptor-carrying sampleable surface. A consumer that only stages/
transfers compressed assets keeps the cheap path; one that samples uses
the sampleable path. `gpu_caps_supports_format` (Phase T) flips from 0 to
1 for compressed-on-native once the corresponding TS bite lands, family by
family (BC first; ETC2/ASTC gated on HW-decode verification).

## Sequencing into 3.2.x minors (Phase TS)

Phase TS slots into the arc **after Phase T (3.2.0) and alongside/after
Phase S–N**, as new minors that grow the arc — nothing here defers past
3.2.x. The bite-level steps:

- **TS.1** *(3.2.x)* — T# image-descriptor builder + format→IMG-format
  table (`native_gfx9_image_descriptor`,
  `native_gfx9_texfmt_to_img_format`), pure Cyrius, every dword + every
  format row CPU-pinned against `gfx9.json`/radv. No HW.
- **TS.2** *(3.2.x)* — S# sampler-descriptor builder
  (`native_gfx9_sampler_descriptor`) + filter/addr constants +
  `gpu_sampler_create` dispatcher + wgpu `WGPUSampler` filler. CPU asserts
  on every dword; mock-slot routing test.
- **TS.3** *(3.2.x)* — `NativeTexture` grow 48→64 (fmt/sw_mode/t_va);
  pass-struct grow (+TEX_DESC_VA); the two new slots
  (`CREATE_2D_SAMPLEABLE` +256, `BIND_FOR_SAMPLE` +264),
  `BACKEND_SIZE` 256→272, `BACKEND_SAMPLE_SLOTS_BEGIN/END`,
  `backend_is_complete` walk. CPU asserts: offsets, size, struct fields,
  mock dispatch.
- **TS.4** *(3.2.x)* — textured FS + UV-export VS in hand-authored GFX9
  ISA (`native_gfx9_shader_textured_load_fs` first — `image_load`, no
  sampler), llvm-mc round-tripped, byte-pinned; FS-input/SPI wiring
  (`SPI_PS_INPUT_ENA`, `SPI_VS_OUT_CONFIG`, `SPI_PS_IN_CONTROL`,
  USER_DATA_PS SET_SH_REG) in the pipeline SH block; RSRC1 high-water.
- **TS.5** *(3.2.x)* — **uncompressed (RGBA8) native sampling MVP**:
  `create_sampleable` (linear BO + T#/S#), `bind_for_sample`, the
  `image_load`/`image_sample` FS path wired into `render_pass_draw`;
  `programs/native_texture_sample_e2e.cyr` on Cezanne — write a known
  RGBA8 texture, sample it across a fullscreen quad, CPU-read the RT,
  verify sampled pixels. **Proves the entire T#/S#/image_sample plumbing
  with zero tiling risk.** Audit re-run (FFI/descriptor bytes).
- **TS.6** *(3.2.x)* — tile-swizzle transform (`native_tile_swizzle_bc` /
  de-swizzle) for the `SW_64KB_S` compressed layout, pure-Cyrius address
  remap from the GFX9 micro-tile equations; CPU asserts: round-trip
  identity (swizzle∘deswizzle = id), known-block placement vs a radv/
  addrlib reference vector.
- **TS.7** *(3.2.x)* — **compressed (BC1/BC7) native sampling**: tiled
  `create_sampleable` + swizzling write/read + the BC `image_sample` FS;
  flip `gpu_caps_supports_format` BC-bit on native;
  `programs/native_compressed_sample_e2e.cyr` on Cezanne — upload BC1
  blocks, sample, CPU-read RT, verify vs a CPU BC1 block-decode (the same
  reference Phase T's wgpu e2e uses). Audit re-run.
- **TS.8** *(3.2.x)* — bilinear sampler (S# filter field + numeric test);
  ETC2 sampling (flip ETC2 cap bit) **iff** HW decode verifies on Cezanne
  (else the code path ships, cap bit stays 0, gap flagged — see hardware
  gaps); update `v3.2-compressed-textures.md` to strike the storage-only
  limitation; CHANGELOG; roadmap; CLAUDE.md (BACKEND_SIZE, struct sizes,
  assert count); P(-1) audit over the descriptor/tiling/shader deltas.

## Exit criteria

- `gpu_texture_create_2d_sampleable` / `gpu_sampler_create` /
  `gpu_render_pass_bind_texture` on both backends; both new slots filled
  (`backend_is_complete` walk over 256..272 active).
- T#/S#/IMG-format builders, tile-swizzle, FS/VS bytes each carry CPU
  assertions — every new path adds one (house rule); every descriptor
  dword and shader dword byte-pinned; format→IMG-format and SW_MODE
  cited against `gfx9.json`/radv.
- **native uncompressed** (TS.5): `native_texture_sample_e2e` samples a
  known RGBA8 texture correctly on Cezanne.
- **native compressed** (TS.7): `native_compressed_sample_e2e` samples a
  BC1 texture, CPU-read RT matches a CPU BC1 decode on Cezanne;
  `gpu_caps_supports_format(BC)` returns 1 on native.
- **wgpu** parity throughout (sample path already present from Phase T;
  the new slots dispatch the existing wgpu sample machinery).
- `v3.2-compressed-textures.md`'s "native = storage-only,
  `GPU_ERR_NOT_IMPLEMENTED` on sample" limitation **struck** and the
  CHANGELOG/roadmap updated to "native compressed sampling shipped".
- lint / fmt (128 KiB cap) / vet / distlib (diff-clean) / version-check
  clean per bite; `dist/mabda.cyr` regenerated; P(-1) audit re-run on the
  descriptor-byte / tiling-math / shader-byte deltas.

## Risks

- **Tile swizzle is the dominant risk.** The GFX9 micro-tile equations
  (`SW_64KB_S`) are intricate; a wrong swizzle silently produces garbage
  sampled pixels (not a crash). Mitigation: TS.5 proves the
  T#/S#/image_sample path on a *linear* surface first (zero swizzle), so
  by TS.6/TS.7 the only new variable is the address remap; the
  round-trip-identity + known-vector CPU tests catch swizzle bugs before
  any HW run; `image_load` (TS.4) gives a no-sampler oracle.
- **T#/S# descriptor field drift.** Image V# field offsets are not all in
  the `gfx9.json` register snapshot (the RESOURCE_TYPE caveat already
  flagged at `backend_native_shaders.cyr:951`). Mitigation: cross-check
  every field against radv `si_make_texture_descriptor` *and* an
  AMD_DEBUG/RADV_DEBUG capture of a real sampled draw; byte-pin the
  resulting descriptor; flag any field that can't be doubly sourced.
- **FS-input/SPI hang quirks.** The solid-red path documents multiple
  Cezanne TDR quirks (SPI_PS_INPUT min, EXP encoding, COL_FORMAT field).
  Adding a real interpolant + MIMG re-enters that territory. Mitigation:
  reuse the proven hang-quirk constants; add the UV varying as the
  minimal delta; budget 2–4 HW iterations (the descriptor-table path's
  original estimate) and verify shader bytes with llvm-mc before each HW
  run.
- **Phase N coupling.** The hand-authored textured FS is the bring-up
  oracle; when Phase N's compiler matures, an `image_sample` op becomes a
  compiler target. TS authors the shader by hand (no Phase N dependency),
  but the op set should be chosen so Phase N can later regenerate it —
  note MIMG as a Phase N op-breadth item, not a TS blocker.
- **Consumer expectation flip.** Phase T told consumers native compressed
  = storage-only. TS flips that. Mitigation: the cap bitset
  (`gpu_caps_supports_format`) is the single source of truth consumers
  already query; flipping the bit per-family as each TS bite lands keeps
  the contract honest (a consumer never samples a format whose cap bit is
  still 0).
