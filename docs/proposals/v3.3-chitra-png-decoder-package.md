# Proposal: `chitra` — a pure-Cyrius raster decoder package (v3.3 PNG)

**Status:** Proposed (v3.3 design, 2026-06-19).
**Arc:** v3.3 "Asset Loading" — companion to
[`v3.3-asset-loading.md`](v3.3-asset-loading.md); tracked in
[`3-3-punchlist.md`](../development/3-3-punchlist.md) Phase **AL.P0**.
**Repo:** a **new sibling AGNOS package** (does not exist yet — created in AL.P0a).

## Summary

`chitra` (चित्र — *image / picture*) is a new pure-Cyrius CPU raster decoder,
a sibling AGNOS package in the mould of `sakshi` / `patra` / `samvada`. v3.3
ships **`chitra` 0.1.0 = PNG → canonical RGBA8**. mabda deps it (a plain dist
dep, **no C shim** — chitra is pure CPU Cyrius, unlike samvada's libsystemd
shim) and uses it for `gpu_texture_load_png`.

The name is deliberately format-agnostic so JPEG/GIF/BMP can join later without
a rename.

## Why a new package, and what it actually is

The maintainer decision was to "stand up a pure-Cyrius decoder package." Two
facts from the tree shape *how*:

1. **Inflate already exists** — the stdlib `sankoch` ships
   `zlib_decompress(src, src_len, dst, dst_cap)` (RFC 1950/1951) + `crc32` +
   `adler32`. chitra deps `sankoch` (via `[deps].stdlib`, **not** a git dep) for
   IDAT decompression — exactly as `kii` does. **DEFLATE is not chitra's work.**
2. **A proven PNG decoder already exists** — `kii/src/png.cyr` (v1.0.1, 813
   lines): W3C-compliant chunk framing, the five PNG unfilter predictors, CRC
   validation, and `kii-fuzz`-hardened guards (decompression-bomb caps, lying-
   IHDR rejection, ratio caps). chitra **forks** this proven core.

**But `chitra` is a fork + real new code, not a rename.** kii is a *terminal
image viewer*; its decoder is shaped for that and is missing what a general
texture loader needs:

| kii's `png.cyr` (as-is) | chitra 0.1.0 needs |
|---|---|
| **Path-based** (`png_decode_*(path, …)`, reads via `io`) | **Byte-buffer** input (`(src, len)` cursor) — mabda hands over in-memory bytes |
| Emits **native channels / palette indices** (color_type 3 → indices; gray not expanded; 16-bit passed through) | **Canonical RGBA8** — gray(0)→RGBA, RGB(2)→RGBA, **palette(3)→RGBA via PLTE**, GA(4)/RGBA(6) normalized |
| **No tRNS** (terminal viewer doesn't need transparency) | **tRNS** alpha synthesis for color types 0/2/3 |
| Fixtures are **PNG files on disk** | Fixtures **embedded as byte arrays** in `tests/tcyr` |

So the genuinely new code is the **byte-buffer I/O boundary** + the **canonical-
RGBA8 normalization pass** (+ tRNS). The chunk walk, unfilter, CRC, and
security hardening port over from kii. This is a **one-time fork**: chitra owns
its copy; kii-bugfix backport is manual and out of scope (no live dependency,
no circular dep — chitra → sankoch-stdlib, mabda → chitra).

## Public API (0.1.0)

```cyrius
# Decode PNG bytes → an owned RGBA8 image. Ok(ChitraImage*) | Err(ChitraErr).
fn chitra_png_decode(src, len): i64               # @public
# Convenience: returns the RGBA8 pixel pointer (w/h via out-params), 0 on error.
fn chitra_png_decode_rgba8(src, len, w_out, h_out): i64   # @public
fn chitra_image_free(img): i64                    # @public

# ChitraImage (32 bytes):
#   +0:  width    (i64)
#   +8:  height   (i64)
#   +16: pixels   (ptr — w*h*4 RGBA8, owned)
#   +24: channels (i64 — always 4 in 0.1.0)
```

`ChitraErr` is a 16-byte record layout-compatible with mabda's `GpuErr` so
mabda can map it cleanly (`chitra` decode failure → `GPU_ERR_IMAGE_DECODE`).

## Scope (0.1.0) and the staged remainder

**In 0.1.0:** PNG signature + chunk parse (IHDR / IDAT-concat / IEND / PLTE /
tRNS), **color types 0/2/3/4/6 at bit depth 8**, sankoch IDAT inflate, the five
unfilter predictors, canonical-RGBA8 output, the kii security guards. **No
interlace** (Adam7) — single-pass only.

**Staged (tracked, not silently dropped):**
- Bit depths 1/2/4/16 → chitra 0.2.
- Adam7 interlace → chitra 0.2.
- **JPEG** → chitra 0.3+ (a larger lift: Huffman + IDCT + chroma upsample;
  the format-agnostic package name reserves room for it). This is the
  "never-silently-defer" home for the v3.3 JPEG deferral.

## Package layout (mirrors sakshi / patra)

```
chitra/
├── cyrius.cyml        — name="chitra", cyrius="6.2.23",
│                        [deps].stdlib=[…, "sankoch", "thread"]; [lib].modules
├── VERSION            — 0.1.0
├── src/
│   ├── lib.cyr        — include chain
│   ├── error.cyr      — ChitraErr (GpuErr-compatible 16-B)
│   ├── png_chunks.cyr — signature + chunk walk (byte-buffer cursor) + CRC
│   ├── png_filter.cyr — the 5 unfilter predictors
│   ├── png_color.cyr  — canonical-RGBA8 (gray/RGB/palette expansion + tRNS)
│   └── png.cyr        — chitra_png_decode + the ChitraImage API
├── programs/smoke.cyr — link-check
├── tests/tcyr/*.tcyr  — CPU assertions (embedded-byte-array fixtures + fuzz corpus)
├── dist/chitra.cyr    — bundle for [deps.chitra] consumers (cyrius distlib)
├── Makefile, scripts/, .github/  — copied from mabda
```

(Split into the per-concern files above if the single-file fork exceeds the
128 KiB lint/fmt cap; kii's is 37 KiB, so it may stay near-monolithic.)

## Bite plan (AL.P0)

1. **AL.P0a** — create the repo + remote; scaffold (cyrius.cyml/VERSION/lib/
   smoke/CI). Smoke links.
2. **AL.P0b** — fork kii's framing + unfilter + security; port kii's asserts.
3. **AL.P0c** — new byte-buffer I/O cursor; `ChitraImage` + accessors + free.
4. **AL.P0d** — new canonical-RGBA8 pass (gray/RGB/palette expansion + **tRNS**);
   embedded-byte-array fixtures (one per color type @ depth 8) → pixel-exact.
5. **AL.P0e** — `chitra_png_decode` / `_rgba8` + `ChitraErr`; carry the kii-fuzz
   adversarial corpus (truncated / lying-length / CRC-fail / decompression-bomb
   → reject, never OOB).
6. **AL.P0f** — distlib + version-check + CHANGELOG + **cut + tag 0.1.0** (the
   cross-repo gate mabda's AL.5 waits on).

## Gates & risks

- **AGNOS-target clone-mutex block.** `sankoch`'s `thread` dep (`mutex_lock` →
  `CLONE_VM`) does not link on `CYRIUS_TARGET_AGNOS` today (kii's CHANGELOG
  records `lib/mmap.cyr: undefined variable 'CLONE_VM'`). chitra inherits it →
  **PNG decode is host-only until the toolchain fix lands.** mabda's KTX2/DDS
  loaders (no sankoch) are unaffected. Tracked; surfaced here so it doesn't
  ambush consumer integration.
- **Cross-repo cut-before-wire.** mabda's `[deps.chitra] tag="0.1.0"` (AL.5)
  cannot resolve until chitra 0.1.0 is cut + tagged (AL.P0f). AL.P0 should run
  in parallel with mabda's AL.0–AL.4 so the tag is ready at convergence.
- **Fork provenance drift.** One-time fork of kii; no live dependency. Future
  kii PNG fixes are not auto-inherited. (Conversely, `kii` may later re-base its
  PNG path onto `chitra` to dedupe — an optional follow-up, not a v3.3 gate.)
- **Security is inherited, not assumed.** Port kii's guards + fuzz corpus
  verbatim; a byte-buffer decoder over untrusted input must keep every
  decompression-bomb / lying-IHDR / bounds guard. New code (the RGBA8 pass) gets
  its own bounds tests.
