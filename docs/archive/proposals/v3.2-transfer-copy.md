# Proposal: v3.2 Transfer Queue → DMA Ring + Public Buffer-Copy API

**Status:** Proposed (v3.2.1 design — Phase X of the v3.2.x arc).
**Date:** 2026-06-15.
**Arc:** Folds the v3.1.x carried-forward "3.1.2" item
(`docs/development/3-2-punchlist.md` § Carried-forward backlog) **into the
3.2.x arc as Phase X / 3.2.1**, per the maintainer directive that the arc
grows to absorb the work rather than deferring it to a patch line.
**Roadmap:** `roadmap.md` § v3.1.1 "Deferred to 3.1.2" + § v3.2.
**Companions:** `v3.1-multiqueue.md` (the queue abstraction this completes),
`v3.2-compressed-textures.md` (the Phase T slot-append precedent it follows).

## Summary

Complete the TRANSFER queue and ship a public GPU-to-GPU buffer copy on
both backends. Four concrete pieces:

1. **Flip `_native_queue_kind_to_ring(TRANSFER)`** from its 3.1.1
   COMPUTE-ring fallback (`src/backend_native.cyr:563`,
   `# 3.1.2 -> _DMA`) to `AMDGPU_HW_IP_DMA`.
2. **A native transfer-copy driver** — `native_transfer_copy_timeline`:
   build a `native_sdma_build_copy_linear` packet into the cached IB,
   submit on the DMA ring via `native_cs_submit_timeline`, signalling the
   TRANSFER queue's persistent timeline and consuming any pending
   cross-ring wait — the exact shape of
   `native_compute_dispatch_cached_timeline`
   (`src/backend_native.cyr:134`), but SDMA on `HW_IP_DMA`.
3. **A guard** so a `gpu_compute_dispatch` (or render) routed onto a
   DMA-ring queue fails loud (`GPU_ERR_TRANSFER`) instead of feeding a
   compute PM4 stream to the SDMA ring.
4. **A public buffer-copy op on a new Backend slot** —
   `gpu_buffer_copy(ctx, src, dst, size)` (default TRANSFER queue) and
   `gpu_queue_transfer_copy(ctx, queue, src, dst, size)` (explicit
   queue, for cross-ring barrier choreography). wgpu fills it with
   `wgpu_command_encoder_copy_buffer_to_buffer` (shim already in tree,
   `src/backend_wgpu.cyr:117`) + finish + submit. Native fills it with the
   SDMA driver. Both real — ADR 006, no stub slot.

The public API is byte-identical on both backends (ADR 005); native gets
real SDMA-engine offload, wgpu gets a correct copy on its single queue.

## Hard truth up front: native has no public buffer object yet

This is the constraint that shapes the design, the way "wgpu has one
queue" shaped multi-queue. The public `gpu_buffer_create` / `_write` /
`_read` slots **are diagnostic stubs on native today**
(`_backend_native_buffer_create` returns 0,
`_backend_native_buffer_write/_read` return `GPU_ERR_NOT_IMPLEMENTED`,
`src/backend_native.cyr:439-453`). Native programs allocate BOs directly
with `native_bo_create_gtt` + `native_gem_va_map` and hand-pack the
private 16-byte `(handle, va)` pair via `native_buf_pair_write`
(`src/backend_native.cyr:361`; `programs/native_compute_store.cyr:154`).

A public `gpu_buffer_copy(ctx, src, dst, size)` needs both backends to
agree on **what a `gpu_buffer` handle is**:

- **wgpu**: the handle is already a `WGPUBuffer` (what
  `_backend_wgpu_buffer_create` returns, `src/backend_wgpu.cyr:82`). The
  copy slot calls the shim with `(encoder, src, 0, dst, 0, size)` — done.
  No representation work.
- **native**: a real GPU-to-GPU copy needs **`(handle, va, size)`** for
  both ends — the SDMA packet wants src/dst **VAs**, the CS BO_HANDLES
  residency list wants src/dst **handles**, and the size guard wants the
  allocation **size**. The bare 16-byte `(handle, va)` pair lacks size,
  and there is no public native buffer object at all.

**Resolution:** Phase X promotes native buffers to first-class objects by
making the existing `gpu_buffer_create` / `_write` / `_read` / `_release`
slots **real on native** (a small `NativeBuf` struct mirroring the
`NativeTex` shape, VA from the existing `native_ctx_alloc_texture_va`
sub-allocator). This is the prerequisite the copy op rides on, and it's a
real, complete implementation — it retires the four diagnostic stubs and
gives native consumers the same `gpu_buffer_*` surface wgpu has. It is
**not** scope creep: the copy op is meaningless without a buffer object to
name on both sides, so the buffer object is part of this feature, planned
as the opening bites of Phase X.

## Current state (what exists today)

- **SDMA copy is HW-proven, not wired.** `native_sdma_build_copy_linear`
  (7-dword COPY_LINEAR, `src/backend_native_pm4.cyr:1125`) +
  `native_cs_submit_4chunk(..., AMDGPU_HW_IP_DMA, ...)` copies a 4 KiB
  page byte-exact on Cezanne (`programs/native_sdma_copy_e2e.cyr`,
  exit 0). The packet builder masks canonical-high VA halves with the
  logical `>>` (`feedback_cyrius_logical_right_shift`).
- **TRANSFER rides the COMPUTE ring.** `_native_queue_kind_to_ring`
  returns `AMDGPU_HW_IP_COMPUTE` for TRANSFER with an inline
  `# 3.1.2 -> _DMA` marker (`src/backend_native.cyr:563`).
  `AMDGPU_HW_IP_DMA = 2` is defined (`src/backend_native_amdgpu.cyr:665`).
- **Timeline submit takes `ip_type`.** `native_cs_submit_timeline(fd,
  ctx_id, bo_list_in, ib_va, ib_bytes, ip_type, signal_syncobj,
  signal_point, wait_syncobj, wait_point, fence_kh, fence_offset,
  ib_flags)` (`src/backend_native_amdgpu.cyr:900`) already routes any ring
  via `ip_type`, signals a timeline point, and prepends an optional
  in-CS TIMELINE_WAIT — exactly what a queue-targeted SDMA copy needs.
- **Queue machinery is complete.** `Queue` carries a persistent timeline
  syncobj + monotonic point + a pending cross-ring wait
  (`src/queue.cyr`); `queue_bump_point`, `queue_pending_wait_*`,
  `gpu_queue_barrier`/`_wait_idle` all land in 3.1.1.
- **wgpu copy shim is in tree.** `wgpu_command_encoder_copy_buffer_to_buffer`
  is used by `_backend_wgpu_buffer_read` (`src/backend_wgpu.cyr:117`) and
  by the legacy `read_buffer_capped` (`src/buffer.cyr:115`).
- **Backend slots end at 256 after Phase T.** 3.1.1 ended at
  `BACKEND_SIZE = 248`; Phase T (3.2.0) appends
  `BACKEND_SLOT_TEXTURE_CREATE_2D_FMT` at +248 → 256.
- **Native `gpu_buffer_*` is stubbed** (see hard truth above).

## Public API (identical on both backends — ADR 005)

```cyrius
# Copy `size` bytes GPU-to-GPU from src buffer to dst buffer on the
# default TRANSFER queue. src/dst are gpu_buffer handles from
# gpu_buffer_create. Returns 0 | GPU_ERR_*. # @public
fn gpu_buffer_copy(ctx, src, dst, size): i64

# Same copy, targeted at an explicit queue (for cross-ring choreography:
# gpu_queue_barrier(ctx, compute_q, transfer_q) then transfer_copy on
# transfer_q resolves the dependency in-CS, no CPU stall). The queue's
# kind selects the ring; a non-TRANSFER queue is rejected on native
# (a copy belongs on the DMA ring). Returns 0 | GPU_ERR_*. # @public
fn gpu_queue_transfer_copy(ctx, queue, src, dst, size): i64
```

`gpu_buffer_copy` forwards to `gpu_queue_transfer_copy` with the cached
TRANSFER queue (`gpu_queue_get(ctx, QUEUE_KIND_TRANSFER)`), exactly as
`gpu_texture_create_2d_rgba8` forwards to `gpu_texture_create_2d` in
Phase T. Both dispatch through one new Backend slot via the ctx-current-
queue stash pattern (`gpu_ctx_set_current_queue`) — no queue param added
to the slot signature, matching the multi-queue precedent
(`v3.1-multiqueue.md` § Public API).

## Backend interface changes

Append **one** slot after the Phase T texture-format slot
(append-after-KIND policy; offsets 0..256 stay load-bearing):

| Slot | Offset | Signature |
|------|--------|-----------|
| `BACKEND_SLOT_BUFFER_COPY` | 256 | `(ctx, src, dst, size) -> 0\|err` |

`BACKEND_SIZE` 256 → 264; add `BACKEND_TRANSFER_SLOTS_BEGIN/END`
(256/264) range markers and **activate** the `backend_is_complete` walk
over the range in this minor — both backends fill the slot for real
(the M.6b / Phase T "activate when both backends fill" discipline; no
deferred range). 4 args is within the fncall ceiling.

The queue-targeting is carried on the ctx stash (`gpu_ctx_current_queue`),
not in the slot signature, so the slot stays at 4 args. The dispatcher
sets the current-queue stash before the slot call and clears it after,
the same shape compute dispatch uses for queue routing
(`src/backend_native.cyr:508`).

## Native buffer object (the prerequisite, bites X.1–X.2)

A `NativeBuf` struct mirroring `NativeTex` (`src/backend_native.cyr:1325`):

```
NATIVE_BUF_FIELD_HANDLE = 0    # KMS handle (residency + release)
NATIVE_BUF_FIELD_VA     = 8    # canonical-high GPU VA (SDMA packet)
NATIVE_BUF_FIELD_ADDR   = 16   # CPU mmap (write/read = memcpy)
NATIVE_BUF_FIELD_SIZE   = 24   # alloc size (copy bound + n== guard)
NATIVE_BUF_STRUCT_SIZE  = 32
```

`_backend_native_buffer_create(ctx, size, usage)` becomes real: page-align
`size` (GEM_VA needs 4 KiB, `reference_gem_va_map_page_align`), VA from
`native_ctx_alloc_texture_va` (rename-agnostic; it's the general per-ctx
VA bump region, 2 GiB at `0xFFFF800180000000`), `native_bo_create_gtt`
+ `native_gem_va_map` with `_NATIVE_PERM_DATA` (R|W), store the four
fields, return the struct ptr (0 on failure). `usage` is accepted for
ABI parity; native GTT BOs are copy-capable by construction (no
COPY_SRC/DST flag needed, unlike wgpu). `_buffer_write` / `_read` collapse
to `memcpy` against `NATIVE_BUF_FIELD_ADDR` with an `n + off <= size`
guard (the texture write/read shape). `_buffer_release` does
`native_gem_va_unmap` + `native_bo_release_gtt`.

This retires the four `GPU_ERR_NOT_IMPLEMENTED`/`return 0` stubs
(`src/backend_native.cyr:439-453`) for real on both backends, so the v0
buffer slots' `backend_is_complete` walk (already active, offsets 16..40)
stays honest.

## Native transfer-copy driver (bite X.4)

`native_transfer_copy_timeline(ctx, src_handle, src_va, dst_handle,
dst_va, size, queue)` — the SDMA analog of
`native_compute_dispatch_cached_timeline`:

1. Pull `fd`, `cid`, cached `ib_handle`/`ib_va`/`ib_addr`, `fence_handle`
   from the ctx accessors.
2. `memset(ib_addr, 0, 4096)`; `native_sdma_build_copy_linear(ib_addr,
   src_va, dst_va, size)` → 28 bytes.
3. Build a 4-entry BO_HANDLES list **(fence, ib, src, dst)** — exactly
   the residency shape `native_sdma_copy_e2e.cyr:87` proved (priorities
   fence=1, ib=10, src=3, dst=3).
4. Read + clear the queue's pending cross-ring wait
   (`queue_pending_wait_syncobj`/`_point` + `queue_clear_pending_wait`),
   so a `gpu_queue_barrier(compute_q, transfer_q)` becomes an in-CS
   TIMELINE_WAIT (no CPU stall) — identical to the compute path
   (`src/backend_native.cyr:170`).
5. `point = queue_bump_point(queue)`; `native_cs_submit_timeline(fd, cid,
   &bo_list, ib_va, 28, AMDGPU_HW_IP_DMA, syncobj, point, wait_so,
   wait_pt, fence_handle, 32, 0)` — `ib_flags = 0` (SDMA needs no
   TC_WB_NOT_INVALIDATE toggle); the DMA engine is cache-coherent for
   GTT.
6. Return `_native_neg_rc_to_gpu_err(rc)`; the caller waits via
   `gpu_queue_wait_idle` / a downstream barrier (async by design — what
   makes overlap possible).

The synchronous public entry (`gpu_buffer_copy` with no explicit queue)
gets the cached TRANSFER queue, submits, then `gpu_queue_wait_idle`s it —
the same wrap `_backend_native_compute_dispatch` uses for the no-queue
case, so a fire-and-forget copy completes before return.

## The DMA-ring mis-route guard (bite X.3)

Once TRANSFER → `HW_IP_DMA`, a `gpu_compute_dispatch` routed onto the
TRANSFER queue (via the current-queue stash) would feed a compute PM4
stream to the SDMA ring — a guaranteed TDR or kernel reject. Add a guard
in `_backend_native_compute_dispatch` (and the render draw path): if
`gpu_ctx_current_queue(ctx)` is non-zero and
`queue_ring(cq) == AMDGPU_HW_IP_DMA`, return `GPU_ERR_TRANSFER`
(fail-loud) before building PM4. Symmetrically, the transfer-copy
dispatcher rejects a current/explicit queue whose ring is **not**
`HW_IP_DMA` on native (a copy belongs on the DMA ring). wgpu's
single-queue aliasing makes the ring check a no-op there (all kinds alias
the one `WGPUQueue`), so the guard is native-only; the public dispatcher
still validates kind on both for portability.

New error code: `GPU_ERR_TRANSFER = 19` (next free after
`GPU_ERR_NOT_IMPLEMENTED = 18`, before `GPU_ERR_OTHER = 99`), with its
`gpu_err_str` row.

## wgpu backend impl (bite X.6)

`_backend_wgpu_buffer_copy(ctx, src, dst, size)`:
`encoder = wgpu_device_create_command_encoder(device, 0)`;
`wgpu_command_encoder_copy_buffer_to_buffer(encoder, src, 0, dst, 0,
size)`; `cmd = wgpu_command_encoder_finish(encoder, 0)`;
`wgpu_queue_submit_one(gpu_ctx_queue(ctx), cmd)` — the byte-for-byte
shape `_backend_wgpu_buffer_read` already runs (`src/backend_wgpu.cyr:116`).
The single WGPUQueue serializes; the TRANSFER queue is a logical alias
(no overlap, correct ordering) — the documented wgpu posture, same as
multi-queue. **Caller-buffer usage note:** wgpu requires
`COPY_SRC` on src and `COPY_DST` on dst at create time
(`WGPU_BUFFER_USAGE_COPY_SRC = 0x0004`, `_COPY_DST = 0x0008`,
`src/wgpu_types.cyr:14`); document on `gpu_buffer_copy` (native GTT BOs
have no such flag, so the requirement is wgpu-specific but stated on the
portable API).

## HW e2e (bite X.7)

`programs/native_transfer_copy_e2e.cyr` (Cezanne) — the cross-ring story
the multi-queue arc set up but never closed end-to-end through the public
API:

1. `gpu_buffer_create` a src + a dst (public API, native real now).
2. `gpu_buffer_write` a known pattern into src.
3. `compute_q = gpu_queue_get(COMPUTE)`, `transfer_q = gpu_queue_get
   (TRANSFER)`. (Optional cross-ring proof: a compute dispatch that
   produces into src on `compute_q`, then `gpu_queue_barrier(ctx,
   compute_q, transfer_q)`.)
4. `gpu_queue_transfer_copy(ctx, transfer_q, src, dst, size)` — SDMA on
   the DMA ring, in-CS waiting on the compute point.
5. `gpu_queue_wait_idle(ctx, transfer_q)`; `gpu_buffer_read` dst;
   assert byte-identical to the produced pattern.

Plus a fail-loud assertion: a `gpu_compute_dispatch` routed onto
`transfer_q` returns `GPU_ERR_TRANSFER` (never reaches the SDMA ring).
The wgpu equivalent (`programs/transfer_copy_e2e.cyr` or folded into an
existing wgpu program) verifies the serialized copy result.

## How it threads the existing patterns

- **Slot append + activate-now:** mirrors Phase T (`+248`, walk active
  this minor) — `+256`, `BACKEND_SIZE` 264, walk active.
- **Queue-targeting via ctx stash:** mirrors compute dispatch
  (`gpu_ctx_current_queue`), no slot-arg growth.
- **Timeline submit + pending-wait consume:** mirrors
  `native_compute_dispatch_cached_timeline` exactly, only `ip_type` and
  the packet builder differ.
- **Native object struct + VA sub-allocator + memcpy write/read:**
  mirrors `NativeTex`.
- **Fail-loud on backend-incapable op:** mirrors Phase T native
  compressed-sample (`GPU_ERR_NOT_IMPLEMENTED`) and the v3-dispatcher
  validation-parity rule (`project_v3_dispatcher_validation_parity`).

## Phasing

See **Phase X** in `docs/development/3-2-punchlist.md`. Shape: native
buffer object (real `gpu_buffer_*`) → DMA-ring flip + mis-route guard →
SDMA timeline copy driver → buffer-copy slot + public dispatchers → wgpu
fill → e2e both backends → cut 3.2.1.

## Exit criteria (3.2.1)

- `gpu_buffer_copy` / `gpu_queue_transfer_copy` on both backends; the
  `BACKEND_SLOT_BUFFER_COPY` slot filled on both (`backend_is_complete`
  walk over 256..264, **active this minor**).
- Native `gpu_buffer_create/_write/_read/_release` are **real** (the four
  3.0 diagnostic stubs retired); a `NativeBuf` round-trip is CPU-tested
  (struct fields, size guard, memcpy) and HW-tested (e2e).
- `_native_queue_kind_to_ring(TRANSFER) == AMDGPU_HW_IP_DMA`
  (CPU-asserted); a compute dispatch on a DMA-ring queue returns
  `GPU_ERR_TRANSFER` (CPU mock + HW).
- native: a public `gpu_queue_transfer_copy` copies SDMA-engine bytes
  byte-identical on Cezanne, including a cross-ring
  compute→barrier→copy→read chain.
- wgpu: same API, serialized copy correct; COPY_SRC/DST requirement
  documented.
- CPU suite: SDMA packet bytes, BO_HANDLES residency layout, timeline
  point accounting, mis-route guard, slot offset/size — each new path
  adds an assertion (house rule).
- lint / fmt (128 KiB cap) / vet / distlib diff-clean / version-check
  green; CHANGELOG `[3.2.1]`; roadmap + CLAUDE.md updated
  (BACKEND_SIZE 264, native buffer real, TRANSFER on SDMA, assert count);
  P(-1) audit re-run over the SDMA CS-submit + new FFI copy path + new
  error code (work-loop step 5: FFI / buffer math changed).

## Risks

- **DMA-ring submit acceptance on this kernel.** Proven once by
  `native_sdma_copy_e2e.cyr` with a binary syncobj + `cs_submit_4chunk`;
  Phase X routes it through `cs_submit_timeline` (timeline signal). The
  timeline submit only swaps SYNCOBJ_OUT for a TIMELINE_SIGNAL chunk and
  is already HW-proven on COMPUTE/GFX — so the residual risk is "DMA ring
  + timeline chunk" specifically; the e2e is the gate. If timeline-on-DMA
  TDRs, the fallback is a binary-syncobj synchronous copy on the DMA ring
  (still a real public op, still SDMA-offloaded) — **not** reverting to
  the COMPUTE ring.
- **Shared cached IB, one copy in flight.** Like the Q.3c compute
  caveat: an async transfer followed by another submit before
  wait/barrier overwrites the IB. Contract: one in-flight queue-targeted
  copy per queue before a wait/barrier (documented; per-submit IB rings
  are a separate later concern).
- **Native buffer-object scope.** Making `gpu_buffer_*` real on native is
  the one piece beyond a pure "flip + slot" — but it is the prerequisite
  for naming buffers on both sides and is bounded (a 32-byte struct + the
  proven BO/VA machinery). It lands as the opening bites, fully inside
  3.2.1, not deferred.
- **`gpu_buffer_copy` usage-flag mismatch.** A wgpu consumer that creates
  src/dst without COPY_SRC/COPY_DST hits a wgpu validation error.
  Mitigation: documented on the public op; the e2e creates buffers with
  the right flags; native ignores the flags (GTT BOs copy unconditionally).
- **VA region pressure.** Native buffers share the 2 GiB texture VA bump
  region (`native_ctx_alloc_texture_va`). For copy-heavy consumers
  (bijli's large transfers) this could exhaust faster; the region is 2 GiB
  and the allocator returns 0 (clean create-fail) on exhaustion. A
  dedicated buffer VA region / free-list is a noted follow-up, but the
  shared region is correct and bounded for 3.2.1.
