# Security Audit — v3.2.0 (compressed textures), 2026-06-15

**Scope:** the v3.2.0 Phase-T compressed-texture diff vs the `3.1.1` tag —
9 src files / ~421 lines: `texture_format.cyr` (new), `wgpu_types.cyr`
(compressed enum values), `capabilities.cyr` (compression bitset),
`error.cyr` (`GPU_ERR_FORMAT_UNSUPPORTED`), `backend.cyr` (texfmt slot +
walk), `texture.cyr` (`gpu_texture_create_2d`), `backend_wgpu.cyr`
(fmt create + block-aware write + caps detect), `backend_native.cyr`
(native fmt create), plus `deps/wgpu_main.c` (device compressed-feature
enablement).

**Method:** P(-1) checklist run as an adversarial workflow — 3 dimensions
(integer-overflow/size-math, input-validation/fail-loud, FFI/ABI) in
parallel, then each non-OK finding independently re-verified against source
to drop false positives.

**Result:** **0 CRITICAL / 0 HIGH / 0 MEDIUM** (one finding was rated
MEDIUM by the finder but downgraded to LOW on verification — fail-loud,
no memory/security impact). 5 LOW findings, **all fixed in T.9** before the
cut.

## Findings + resolutions (all LOW, all fixed)

| # | Class | Location | Resolution |
|---|-------|----------|------------|
| 1 | fail-loud | `_backend_wgpu_texture_read` not block-aware (write slot was; read still used `w*h*4`) — compressed read mis-validated | **Fixed:** read slot now reads `fmt` at tex+16 and returns `GPU_ERR_NOT_IMPLEMENTED` for compressed (256-padded block readback is a future enhancement; native compressed read works via memcpy; wgpu consumers do a padded copy-back as the e2e does). + CPU test. |
| 2 | input-validation | `_backend_wgpu_texture_create_2d_fmt` lacked the redundant 8192 dim cap its native sibling has | **Fixed:** added `validate_dimensions` guard (slot-independence, per the v2 MED-1 pattern). Was unreachable (dispatcher caps first; downstream self-defends) — defense-in-depth. |
| 3 | fail-loud | create slot relied on wgpu's own validation for an adapter-unsupported family → `wgpuDeviceCreateTexture` **aborts the process** (uncaptured wgpu error) | **Fixed:** create slot now checks `gpu_caps_detect_texture_compression(adapter)` and returns 0 for an unsupported family — graceful fail-loud instead of abort. |
| 4 | doc | `texture_format.cyr` comment claimed the create path "returns `GPU_ERR_FORMAT_UNSUPPORTED`" — the pointer-returning create only signals via 0 | **Fixed:** comment corrected (code is for consumer pre-check / future Result variant). |
| 5 | fail-loud | (same root as #1) public `gpu_texture_read` on a wgpu compressed texture returned wrong bytes silently | **Fixed by #1** (now fail-loud). |

**Notes:** native compressed storage round-trip + the block math + the v29
enum mapping + the block-aware write + the overflow/dim-cap guard all
verified correct (OK). The block multiply is bounded by the 8192 dim cap
(worst case 256 MiB RGBA8 / 64 MiB compressed, both far under i64).

Post-fix gate: 2434 CPU asserts (0 failed), lint/fmt/vet clean, dist
idempotent; `compressed_texture_e2e` (wgpu) + `native_compressed_store_e2e`
+ the full GPU program suite pass on Cezanne.
