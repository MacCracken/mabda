# Mabda Security Audit — 2026-11-16 (4.3.1, render tier MB2–MB5)

**Scope.** The 4.3.1 diff, weighted toward what crosses a trust or ABI boundary:

- the launcher revision (`deps/wgpu_main.c`, 81 → 83 slots: `wgpuComputePassEncoderRelease`,
  `wgpuComputePipelineGetBindGroupLayout`) and their Cyrius wrappers (`src/wgpu_ffi.cyr`);
- the unified wgpu texture record (`src/backend_wgpu.cyr`, 80 bytes, replacing three 32-byte
  layouts) and every path that reads it: writes, readback, views, copies, bind groups, passes;
- the new descriptor writers: colour / depth attachments, texture and view descriptors, copy
  infos, the compute pipeline descriptor, the surface configuration (`src/backend_wgpu_target.cyr`,
  `_ctier.cyr`, `_surface.cyr`), and the per-context scratch block they share;
- the public builders and dispatchers that take consumer data (`src/gpu_target.cyr`,
  `src/gpu_compute_tier.cyr`, the MB5 half of `src/surface_v3.cyr`);
- `gpu_compute_dispatch` on wgpu (the binding array, the per-module pipeline cache), the wgpu
  buffer readback rewrite, the KTX2 / DDS container mapping for the uncompressed render formats
  (`src/asset_format.cyr`, `src/asset_load.cyr`), and the native subset fillers
  (`src/backend_native_rtier.cyr`).

**Method.** One reviewer reading the diff against the CLAUDE.md security checklist (input
validation, buffer safety, integer overflow, divide-by-zero, syscall returns, pointer validation,
FFI descriptor offsets, shim correctness), plus a regression check of the prior audit. Every v29
struct offset the diff writes was taken with `offsetof` against
`deps/wgpu-native/include/webgpu/webgpu.h` (v29.0.1.1) and is pinned byte for byte by
`tests/tcyr/target_tier.tcyr` through a mock function table that copies each descriptor during the
call. The VkFormat / DXGI_FORMAT numbers were taken from `vulkan_core.h` (KhronosGroup
Vulkan-Headers, fetched 2026-11-16) and the system `dxgiformat.h`.

## Verdict

**0 CRITICAL / 0 HIGH / 1 MEDIUM / 5 LOW — all fixed in 4.3.1.** Most were found while building
MB2–MB5 on paths those milestones put into use.

| ID | Severity | Where | Status |
|---|---|---|---|
| MED-1 | Medium | `src/backend_wgpu.cyr` — `_backend_wgpu_buffer_read` returned 0 with stale bytes for an unaligned window | **Fixed**, CPU + HW test |
| LOW-1 | Low | `src/backend.cyr` — `backend_get_slot` on a null backend loaded from address `off` | **Fixed**, test |
| LOW-2 | Low | wgpu compute passes leaked their encoder; per-call heap allocations on the readback paths; the legacy `compute_dispatch` leaked both encoders | **Fixed**, HW RSS check |
| LOW-3 | Low | `src/backend_wgpu.cyr` — three wgpu texture layouts: a readback of a mipped texture read its width as its format | **Fixed** (one record), tests |
| LOW-4 | Low | `src/depth.cyr` — `depth_stencil_state` wrote `WGPUOptionalBool` 2 (Undefined) for depth writes | **Fixed**, test |
| LOW-5 | Low | `src/backend_wgpu.cyr` — two configured surface records sharing one `WGPUSurface` released it twice | **Fixed**, test |

### MED-1 — the wgpu buffer readback returned stale bytes as success

`_backend_wgpu_buffer_read` copied `[off, off + n)` with `wgpuCommandEncoderCopyBufferToBuffer`.
WebGPU copies whole 4-byte words; an unaligned offset or size makes the command buffer invalid.
Since 4.3.0 the launcher's finish shim refuses an invalid command buffer (NULL) and the submit shim
skips NULL — so nothing was copied, the function went on to map its fresh staging buffer and
returned **0 with zeros** in the caller's buffer. A consumer reading a 5-byte field of a storage
buffer got silent wrong data. The encoder was also never released, and a refused command buffer
was not checked at all. **Fix:** the copy window is widened to word bounds and the requested bytes
taken from inside it; a refused copy returns the recorded error; the encoder is released.
`test_wgpu_buffer_read_window` (CPU, the copy window and the refusal) and `compute_tier_e2e` part A
(HW: offset 2, 5 bytes, compared with the aligned read).

### LOW-1 — `backend_get_slot(0, off)` dereferenced address `off`

A context that was never wired (or a zeroed stack context) reached `backend_get_slot` with a null
backend from the texture dispatchers, which then `fncall`ed the loaded word: a segfault. Found by
`texture.tcyr` once 4.3.1 let the render formats past the format guard. **Fix:** `backend_get_slot`
returns 0 for a null backend; `gpu_texture_create_*`, `gpu_texture_write*`, `gpu_texture_read` and
`gpu_texture_generate_mipmaps` check for a missing slot.

### LOW-2 — leaks on the compute and readback paths

- The 4.3.0 launcher had no `wgpuComputePassEncoderRelease`: every wgpu compute pass would have
  leaked its encoder (per frame for soorat's particles). Slot 81 (4.3.1) releases it; an 81-slot
  launcher refuses compute passes with `GPU_ERR_FFI_SYMBOL` instead of leaking.
- The legacy device-based `compute_dispatch` released neither its pass encoder nor its command
  encoder and bump-allocated its pass descriptor; `wgpu_buffer_map_sync` bump-allocated its 8-byte
  status word, and the texture and buffer readbacks their 48-byte staging descriptors — on every
  call. All on the stack now, encoders released.
- HW: `compute_tier_e2e` part D runs 160,000 compute passes: 0 bytes of Cyrius heap, and RSS flat
  over the 40,000 after the wgpu-core warm-up (measured first: 50k-pass windows grew 11.5 MiB,
  1.8 MiB, then 0, 0, 0, 0 — an empty encoder + submit warms up the same way).

### LOW-3 — three texture layouts

The wgpu backend's plain textures kept the format at +16 and the size at +24; mipped textures kept
the size at +16 and the format at +28; arrays and cubes kept the layer count where the mipped ones
kept the level count. `gpu_texture_read` of a mipped texture read its width as its format and its
mip count as its height. **Fix:** one 80-byte record for textures, targets, views and surface
frames (layout in `src/backend_wgpu.cyr`); every reader uses it; `target_tier.tcyr` and
`backend.tcyr` pin it.

### LOW-4 — `depth_stencil_state` wrote Undefined

The legacy depth-state builder stored 2 at `depthWriteEnabled` as "true"; in v29 `WGPUOptionalBool`
is False 0 / True 1 / Undefined 2, and wgpu rejects Undefined for a depth format. **Fix:** 1;
`graphics.tcyr` pins it.

### LOW-5 — a shared `WGPUSurface` released twice

`gpu_surface_configure` makes a new record each call (a reconfigure with another present mode);
the records share the context's `WGPUSurface`. Releasing both called `wgpuSurfaceRelease` twice on
one handle. **Fix:** a record releases the surface only while it is still the context's current
one (`gpu_surface_release` clears that after the first); `test_wgpu_surface_bytes` checks one
release for two records.

## Reviewed and found sound

- **Launcher.** Slots 81–82 are plain function pointers (no shim); `build_fn_table` aborts at
  start-up if the table and `FN_COUNT` disagree; `launcher.tcyr` reads `FN_COUNT` out of the source
  and every fake table in the tests was resized to 83 x 8 bytes (the 81 x 8 ones would have been
  overrun by the installers). An 81-slot launcher: compute passes and `gpu_compute_dispatch` return
  `GPU_ERR_FFI_SYMBOL`, `gpu_caps_wgpu_shader_f64` reports 0.
- **Descriptor offsets.** Colour attachment 72 B (view +8, depthSlice +16, resolve +24, ops
  +32/+36, clear +40), depth attachment 48 B (view +8, ops +16/+20, clear f32 +24, read-only +28;
  stencil ops Undefined for Depth32F), texture 80 B, view 64 B, copy info 32 B, extent 12 B, compute
  pipeline 80 B (entry point `{NULL, WGPU_STRLEN}` for the module's one entry), surface
  configuration 64 B, surface texture 24 B — all offsetof-checked and pinned.
- **Scratch block.** 8 colour attachments (576 B), the depth attachment, the blit cache, the compute
  descriptor and pass record and the dispatch-cache pointer fit before `_WGPU_RS_SIZE` (9112);
  `test_constants` asserts each boundary. Descriptors are consumed during the wgpu call, so reuse is
  safe; open pass records are never shared.
- **Consumer data.** Targets: dimensions ≤ 8192, a colour or depth render format, 1 or 4 samples.
  Pass descriptors: ≤ 8 colour attachments, known load / store ops, a clear colour for CLEAR, clear
  depth in [0, 1], read-only 0 / 1; the backend refuses before wgpu a released, non-renderable,
  multi-level or multi-layer attachment, attachments of different sizes, depth in a colour slot and
  colour in the depth slot, and a resolve target for a single-sample attachment. Views: a known
  dimension, non-negative ranges inside the texture's levels and layers, one layer for 2D, six for a
  cube, a multiple of six for a cube array. Copies: non-negative origins, sizes ≤ 8192, the
  rectangle inside both objects, copy-compatible formats (sRGB twins), the usage bits, no
  multisampled depth. Writes: the level and layer inside the object, the exact block-aware size,
  depth refused (WebGPU has no depth32float upload), `COPY_DST` required. Reads: the exact
  `width x height x bytes per texel` of the level. Compute: ≤ 4 contiguous groups, dynamic offsets
  256-aligned, workgroup counts through `validate_dispatch`, a binding array of ≤ 16 non-null
  buffers. Surfaces: dimensions ≤ 8192, a listed format, a present mode the surface offers (or an
  AUTO mode resolved against the list), the frame status mapped to `GPU_ERR_SURFACE_*`.
- **Integer math.** The texture readback's staging size is `padded_row x (height - 1) + row`: at
  8192 x 8192 RGBA16F, a 64 KiB row and ~512 MiB, far inside i64; above wgpu's buffer limit the
  staging create is refused, the copy is refused, and the error is returned. Copy rectangles sum to
  ≤ 16,384. View sizes come from `mip_level_dim` (never below 1). No new divisor can be zero (the
  dispatch cache's modulus is the constant 32).
- **Dispatch cache.** 32 entries per context; an evicted entry's pipeline and layout are released
  (wgpu keeps alive what in-flight work uses); a released shader module is forgotten, so a later
  module at the same address never reuses its pipeline (`test_wgpu_compute_bytes`).
- **Wayland test client.** `programs/surface_wayland_e2e.cyr` resolves `dlopen` / `dlsym` from the
  process's own loaded `libc.so.6` (an ELF GNU-hash lookup of its in-memory dynamic symbols) and
  only loads `libwayland-client.so.0`; the xdg-shell interface tables it builds are static data.
  Test-only; nothing in `src/` does this.
- **Containers.** RGBA8 sRGB, BGRA8 (+ sRGB) and RGBA16F KTX2 / DDS formats map to their own ids;
  `gpu_ctx_supports_format` admits them on wgpu and refuses on native the two the native sampler
  has no T# for (BGRA8, RGBA16F); native keeps sampling RGBA8 sRGB as RGBA8, as before 4.3.1.
