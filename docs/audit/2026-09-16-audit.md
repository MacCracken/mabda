# Mabda Security Audit — 2026-09-16 (4.1.3 P(-1))

**Scope.** Full P(-1) pass at the 4.1.3 cut (cyrius 6.6.4), weighted toward what changed since the
last full sweep (`2026-07-01-audit.md`, v4.0.0):

- the 4.1.0 native SPIR-V → GFX9 compiler extensions (loops, `OpPhi`, f32 division,
  integer-condition `OpSelect`) that consume **consumer-supplied SPIR-V**;
- the 4.1.2 dependency moves: chitra 0.3.1 → 1.0.3 (PNG/JPEG bytes) and samvada 0.4.1 → 1.0.1
  (native dbus);
- the 4.0.7 NVIDIA multi-size BO allocator;
- the 4.1.3 changes: render owned-state stream, `GPU_ERR_DEVICE_LOST` reset detection,
  `rtb_build` validation, and the test/bench fixes.

**Method.** One reviewer reading the code directly against the CLAUDE.md security checklist:
input validation, buffer safety, integer overflow, divide-by-zero, syscall returns, pointer
validation, FFI offsets. Also a regression check of prior findings and an external CVE sweep.
Each fixed finding was proven with a CPU test run against the pre-fix code, and the touched
native paths were re-run on hardware.

- **2026-07-01 findings and the 2026-06-14 ship-blockers:** the code they cite is unchanged or

## MED-1 (fixed) — untrusted SPIR-V `<id>` indexes `vals[]` before it is bounded

**Class:** out-of-bounds read from untrusted input (consumer-supplied SPIR-V on the native
shader-create path). **Impact:** a crafted module crashes the host process (SIGSEGV). The value
read is discarded when `mir_emit` then rejects the id, so nothing leaks and nothing is written.

The lowering pass bounds almost every operand before `mir_val_*` reads it. Three sites did not:

1. `_spirv_emit_phi_moves`: `mir_val_type(m, result)` where `result` is the target block's
   `OpPhi` result `<id>`. On a forward branch that `OpPhi` has not been lowered (and so not
   bounded) yet. This code arrived with the 4.1.0 loop/phi work.
2. The ordered f64 compare path: `mir_val_type(m, fa)` on the first operand.
3. `OpConvertFToS`: `mir_val_type(m, spirv_word(ptr, off + 3))`.

`mir_emit` bounds result and operand ids, but each of these reads ran first with the raw id
(for example `0x7FFFFFF0` → `vals + ~85 GiB`).

**Fix.** A `_spirv_val_type(m, id)` helper returns `MIR_T_VOID` for id 0 or `id >= cap_ids`,
used at sites 2 and 3. Site 1 bounds `result` and fails with `MIR_ERR_ID_OOR`.
**Test.** `compiler_lower.tcyr` `test_spirv_lower_untrusted_ids_bounded` (+7 assertions). On
the pre-fix code the suite dies with SIGSEGV (exit 139); on the fixed code, 460/460 pass.

## LOW-1 (fixed) — compute dispatch primitives trust their stream length and binding count

`native_compute_dispatch_cached`, `_cached_n`, `_cached_timeline` and `_cached_n_timeline` are
unprefixed and ship in `dist/mabda.cyr`. They `memcpy(ib, pm4, pm4_bytes)` into a 4096-byte IB
slice, and the `_n` variants write one entry per binding into a 32-entry stack array. The public
path is safe: `_native_dispatch_compiled` caps bindings at 16 and builds the PM4 itself. A
direct caller, though, could overrun the IB mapping or the stack.
`native_render_dispatch_simple` got the same guard earlier in 4.1.3.

**Fix.** Reject `pm4_bytes <= 0 || > _NATIVE_IB_SIZE` and
`n_binds < 0 || > _NATIVE_DISPATCH_MAX_BINDS` (28) before any staging.
**Test.** `native.tcyr` `test_native_compute_dispatch_bounds` (+9 assertions).
**HW.** Cezanne: compute-store, spirv-saxpy, spirv-public-api, spirv-queue-dispatch,
multiqueue, render-graph-mq, spirv-loop and transfer-copy all pass, with no kernel GPU messages.

## LOW-2 (fixed in 4.1.4) — loaders leak the texture when a step after the create fails

`gpu_texture_load_{png,jpeg}{,_mipped}_result` and the KTX2/DDS paths create the texture, then
`return gpu_err_result(...)` on a failed write, mip generation or a later container check,
without `gpu_texture_release`. It is resource hygiene, not memory safety: the handle is still
valid and nothing is corrupted.

**Fix (4.1.4).** `_asset_release_fail(ctx, tex, code)` releases the texture and returns the error
at all 25 post-create failure returns (PNG/JPEG single and mipped, KTX2 and DDS single and
layered). `gpu_texture_release` now returns 0 for a backend with no release slot instead of calling
a null function pointer. **Test.** `asset_load.tcyr` counts releases through a mock backend slot: a
truncated DDS, an out-of-range KTX2 `byteOffset` and a truncated DDS array each release exactly
the texture they created, and a successful load releases nothing.

## Verified sound (reviewed, no finding)

- **SPIR-V parser** (`spirv_parse.cyr`): the header gate (magic, `id_bound` < 2^30, word cap)
  runs before any walk. `spirv_validate_stream` rejects zero and truncated word counts, and the
  driver requires it to return 0. Each table builder rejects `id_bound > cap` and guards every
  per-id write.
- **Lowering** (`spirv_lower.cyr`, `mir.cyr`): `_mir_lower_type` bounds the type id and its
  vector component id, and limits recursion to one level. Access chains bound
  `rty/base/midx/aidx`. The value, instruction and pointer tables fail loud at capacity.
  `_spirv_find_label` / phi scans stop on a zero word count.
- **chitra boundary** (`asset_load.cyr`): the decode result, `w > 0` and `h > 0` are checked,
  and the 8192 texture-dimension cap bounds `w*h*4` before the write. chitra 1.0.3 has its own
  audit (`chitra/docs/audit/2026-09-10-audit.md`).
- **samvada boundary** (`surface_v3.cyr`, `-D MABDA_LOGIND`): unchanged since the v4.0.0 audit
  except comments. samvada 1.0.x was audited 2026-09-09 (A lane closed at 1.0.1).
- **Buffers:** native AMD and NVIDIA write/read use `off > size` and `n > size - off`
  (overflow-safe). Create sizes are capped before alignment (`_NATIVE_TEXTURE_VA_REGION`,
  `NV_BO_MAX_SIZE`). The copy checks both sizes.
- **NVIDIA allocator (4.0.7):** size is capped before `_nv_align64k`, VA exhaustion is checked
  against the kernel reservation, and the BO is released on VA or bind failure.
- **4.1.3 reset detection:** a failed `QUERY_STATE2` fails closed, the settle sleep retries on
  EINTR, and RAS counters are excluded from the verdict. Note: the op needs Linux ≥ 4.17 (2018);
  an older kernel would fail every native dispatch as device-lost.
- **4.1.3 render stream:** the composer's capacity is checked before it writes past the scratch
  buffer, and `native_render_dispatch_simple` bounds the stream to one IB slice.
